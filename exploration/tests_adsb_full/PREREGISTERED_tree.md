# ADS-B inside the tree model — pre-registration

Written 2026-10-01, before any tree is retrained, at the user's request ("after it is done
downloading please proceed with the retraining"). Board: v46 = 272.2619 is the last upload; v47
(corrector B) is built and not yet uploaded.

**Prior expectation** (from the interaction check): small. v47's corrector B already learns ADS-B ×
tabular interactions, and the tree is about 1/3 of the blend.

## What changes

- **Arm:** `airport_operator_blend` (per-airport + per-operator LightGBM, one global alpha).
- **Change:** it gets 7 extra columns, the `all_nd` ADS-B features (`e_first`, `e_disp`, `e_move`,
  `liftoff_dt`, `stop_s`, `lineup_s`, `med_gs`).
  - They are attached by `MVT_ID_mvt` from the strict-matched per-day estimates.
  - They are NaN outside the 7 corrected airports (EDDF, EHAM, LEBL, EDDM, LSZH, LEMD, EGLL), and
    NaN where there is no match.
  - All of 2025 is fetched (365 days, after the Feb–Jun integrity check).
- **Everything else is identical:** parameters, featureset, `keep_all`, seed 42.
- **Tag:** `adsb`.

**Runs:**
- `forward_inner`, `forward` and `seasonal_full` with `--adsb`;
- `full` with `--adsb --freeze-from` the forward `adsb` model.json, only after a PASS.

**Fairness control:** the old tree's predictions are regenerated by the same prediction script from
the existing untagged runs. The comparison therefore differs only in the 7 columns.

## Decision surface: seasonal_full test (Jan + Jul 2025)

| variant | base | corrector |
|---|---|---|
| X | `(tree_old + mlp6 + ftt) / 3` | a v47-style corrector (B inputs, v46 parameters, 7 airports) trained on **Aug–Dec 2025 only**, on the old held-out bases |
| Y | `(tree_adsb + mlp6 + ftt) / 3` | the same corrector design, retrained on **Aug–Dec only**, on the new held-out bases |

- New bases: `tree_adsb` from `forward_inner` (Aug) and `forward` (Sep–Dec).
- Jan and Jul are not used by any corrector here. A v46 or v47 model must not be used, because they
  trained on Jan and Jul.
- Also reported: Y with no corrector, and the tree arm alone (old vs new).

**PASS requires:**
- Y < X on pooled RMSE over Jan + Jul;
- Y < X in Jan and in Jul separately.

## After a PASS (v48), before upload

- Fit the `full` tree.
- Re-solve the per-airport blend weights on `forward_inner` with the new tree, using the existing
  solver.
- Rebuild the v42-equivalent base with the new tree; the LIRF override is unchanged.
- Train corrector B on the new held-out bases over all 7 months.
- Check that it rebuilds byte-identical, and write the expectation before upload.
- If it scores worse than the then-last best, re-upload that file last.

**Cut-off:** if v48 cannot be built by 2026-10-06, stop. v46 or v47 stays final.

**FAIL →** closed: ADS-B stays in the corrector only.
