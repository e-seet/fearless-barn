**Status: `STATUS: in progress`.** This is a **coordination + results snapshot**,
not a write-back. Nothing here is registered in `INDEX_MODE2.md` or folded into
`methodology/`. It exists so the two agents working this build — **Claude** and

## 0. Ownership rule

Owner is assigned by **folder-name suffix**:

| suffix | owner | corroboration |
|---|---|---|
| `pipeline_*_antigravity` | **Antigravity** | `README.md` §4 independently labels these "third-party" |
| `pipeline_*` (no suffix) | **Claude** | `RETROSPECTIVE.md` is Claude's (Opus 5); these are its arms |

Git cannot attribute — every commit is authored `eddie`. Ownership here is about
*who designed the arm*, not who pressed run: this is a live multi-agent build and
either agent may execute any arm.

The two agents **share one library and one protocol**: `common/`, `config.py`,
and the artifact-keying + gate rules in `compare.py`. Every arm is trained on the
same pool (`d16701419a0d1c8703890a73c854ce9c`, n=1,387,105), the same `forward`
split, the same `keep_all` outlier policy and the same feature fingerprint
(`47cba1fb5f800c8d`), so the comparison isolates the modelling idea.

### Fix applied this pass (`MISTAKES.md` #85)

`multimodel_antigravity`, `delay_twostage_antigravity` and
`feature_pruned_antigravity` wrote the training-pool hash under the key
`train_pool_fingerprint`; `compare.py`'s pool gate reads `train_pool_ids_sha`
(as every other arm writes it). The gate therefore saw no hash for those three
and, while they were still being run, ranked the subset that had eval files and
printed `[PASS]` — with the eventual winner outside the field. Key renamed (same
value, `D.pool_fingerprint(Xtr.index)`), arms re-run, every RMSE identical to
before, `compare.py` re-run over the full field.

### 2.1 `per_airport_antigravity` ≡ `per_airport` — pure duplication

**Byte-identical output at all three seeds:**

| seed | `per_airport` val / test | `per_airport_antigravity` val / test |

| 42 | 282.66 / 287.36 | 282.66 / 287.36 |
| 43 | 282.54 / 287.81 | 282.54 / 287.81 |
| 44 | 282.37 / 288.34 | 282.37 / 288.34 |

Same model, same library, duplicated compute (incl. a 3-seed sweep run twice).
**Action: drop one.** Keep `pipeline_per_airport` (parent of `per_airport_stack`
and `cross_blend`); retire `pipeline_per_airport_antigravity` or repoint it.

### 2.2 `multimodel_antigravity` vs `cross_blend` — the same lever, built twice

Both are **per-airport convex blends of the per-airport family against the neural
family, weights fitted on the held-out `forward_inner` surface.** They differ only
in which parents, and (for `cross_blend`) which weight mode. Both now have a
3-seed sweep for the `forward_inner` mode:

| implementation | parents | mode | val (42/43/44) | test (42/43/44) | test in-band 42 | 3-seed mean test |
|---|---|---|---|---|---|---|
| `multimodel_antigravity` | `per_airport` + `mlp_antigravity` | forward_inner | 250.32 / 253.40 / 255.79 | 241.60 / 251.59 / 250.76 | 223.76 | **247.98** |
| `cross_blend` `w_inner` | `per_airport_stack` + `ensemble_antigravity` | forward_inner | 250.76 / 253.11 / 256.45 | 243.49 / 252.31 / 253.61 | 222.40 | 249.80 |
| `cross_blend` `w_inner_tuned` | + per-airport-tuned per-airport model | forward_inner | 250.24 | 243.50 | 222.49 | — (seed 42 only) |
| `cross_blend` `w_per_airport` | `per_airport_stack` + `ensemble` | val (in-sample) | 250.34 | 246.38 | 224.27 | — (seed 42 only) |
| `cross_blend` `w_global` | same | one global scalar | 253.05 | 265.00 | 241.28 | — (seed 42 only) |

**On the 3-seed sweep the two clean implementations are a statistical tie:** mean
test 247.98 vs 249.80, mean val 253.17 vs 253.44, each with a ~10 s test seed
spread. `multimodel` edges the pooled metric by ~2 s; `cross_blend w_inner` edges
the in-band metric by ~3 s (mean 224.4 vs 227.5). Both independently confirm the
mechanism: **LIRF → weight 0.000 (fully neural), the other nine airports 0.64–0.95
(lean per-airport)**, and both beat their parents at 9 of 10 airports.

**Action:** treat this as **one arm family with two implementations**, not two
arms. Pick one to carry forward and fold the other's parent choice in as a
`--parents` option rather than a second folder. `compare.py` can only see
`multimodel_antigravity` (§3a).

### 2.3 `lightgbm_arrfeat` + `per_airport_arrfeat` — paired on purpose, **not** duplication

Both add the same 7 arrival/runway-queue columns, but to different bases, to
answer a question the pooled version structurally cannot: the stand taxi-in ↔
taxi-out correlation flips sign by airport (EHAM +0.90 … LEBL −0.24), so a pooled
model averages the signs to noise while a per-airport model can use each one.
**Keep both.**

### 2.4 `ensemble_antigravity` vs `cross_blend` — softer overlap

Both are blenders. `ensemble_antigravity` is a **global** NNLS over five base arms
fitted on **val labels**; `cross_blend` is a **per-airport** blend of **two
families** fitted on **`forward_inner`**. Different enough to keep both — but a
third blender is probably not needed.

### 2.5 Emerging: the `_tuned` family (seed-42-only, still settling)

`per_airport_tuned` (§4) produced a per-airport HP config that is now being fed
into two downstream arms as tagged variants: `per_airport_stack tag=inner2_tuned`
(val 278.81 / test 286.10) and `cross_blend tag=w_inner_tuned` (val 250.24 / test
243.50). All three are **seed 42 only** — do not rank them against swept arms yet.

## 4. `per_airport_tuned` — result (was "built, not run")

Ran this pass. It reports three numbers from one sweep of 6 LightGBM configs
across the 10 airports:

| | what | val RMSE |
|---|---|---|
| **A** | pooled arm's default config, every airport (= plain `per_airport`) | 282.66 |
| **B** | best *single* global config (`lr02_lv511_md50`), one val selection | 279.29 |
| **C** | each airport takes its own best config, ten val selections | 279.18 |

- **C − B = −0.12 s.** Per-airport HP tuning buys **nothing** over tuning once
  globally; the 9 extra selections are pure optimism.
- **B − A = −3.37 s.** The default config was a slightly poor choice; picking one
  better config globally is the real (small) gain.
- Test (config C): pooled 286.31 / in-band 223.18.

**Conclusion: tune once globally (`lr02_lv511_md50`), do not tune per airport.**
The `_tuned` downstream variants (§2.5) inherit the ~3 s B−A gain, not a
per-airport effect.

Nothing else is code-complete and unrun.
