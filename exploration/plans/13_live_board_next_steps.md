## 4. The refit (only if v18 says "in-band")

**You cannot train on 2026 — the scored set has no labels.** Everything is
trained on 2025. "Refit" = make a 2025-trained model lean toward the 2025
conditions closest to 2026.

### 4a. Narrow (cheap, ~minutes, low expected payoff)

Re-solve the 10 per-airport tree/MLP blend weights on the **latest 2025 months
(Nov–Dec)** instead of the current mid-2025 `forward_inner` holdout. Those 10
weights are known to be very stable (LIRF → ~0 neural, others 0.64–0.95), so
don't expect much.

### 4b. Real (hours, the actual lever if the gap is in-band)

**Recency-weighted retrain** of the base models — `per_airport`, `per_operator`,
`mlp_antigravity` — exponentially down-weighting early-2025 rows so the models
track late-2025 patterns nearest the 2026 scored window. Then rebuild
`airport_operator_blend` → `airport_operator_multimodel` (`--tag msmlp`,
seeds 42/43/44) → submit.

`pipeline_lightgbm_recency` already exists, filed **tier C "no effect"** — but its
own note says *"the forward split can't test the real 13-month horizon."* **The
live board IS that horizon.** So recency weighting is genuinely untested on the
thing that matters, and it directly targets a 2025→2026 shift.

## 5. Reference — mechanics

- **Rebuild a submission:** `python submit.py --arm <A> --split full --featureset
  with_aobt --outlier-policy keep_all --seed 42 [--tag <T>] --version <N> --force`
  (re-predicts against whatever `ranking.parquet`/`submitting.parquet` are in
  place; no training).
- **`full` split base retrain:** `python pipeline_<arm>/train.py --split full
  --seed 42 --outlier-policy keep_all --tag <T> --freeze-from
